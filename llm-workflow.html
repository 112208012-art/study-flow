LLM Wiki 建置、查詢、檢查與生成紀錄

先討論，再生成

這次以既有的 StudyFlow 專案方向為基礎。製作前先規劃受眾、教學問題和 Wiki 的粒度：讓第一次做週計畫的大學生，學會處理報告與考試集中在一週的狀況。接著決定把資料做成五張來源卡，再彙整成四個能獨立查詢的條目。以同一個報告與統計考試情境串起七頁。

實際查詢使用三個問題：「如何看一週的期限與空檔？」對應 W1，「如何把報告拆開？」對應 W2，「如何安排多次複習並知道自己會不會？」對應 W3 · W4。

Loop / Graph

  1. 取得資料並逐篇入庫。確認來源機構、擷取段落與主張範圍，再建立 S1–S5。段落找不到時回到搜尋。
  2. 查詢 Wiki。依教學問題挑條目，整理成含條目與來源 ID 的大綱。缺條目時回到查詢或補入庫。
  3. 逐條比對摘要、例子與原文。主張超出來源或意思有偏差時，重寫該條大綱並再檢查。
  4. 通過後生成 HTML。檢查引用錨點與簡報操作。若版面或按鈕有問題，修 HTML 後重跑。若內容有問題，回到大綱證據檢查。

逐篇入庫和逐條檢查都會重複。先處理主張偏差，可以避免同一錯誤進入案例與課後練習。

反思

這次問題集中在「把概念改寫成教學大綱」節點，六個主張裡有兩個偏差。第一個把來源的排程例子寫成所有人都要遵守的規則，第二個把熟悉感和從記憶回答混在一起。

原本預計在投影片成稿後檢查內容。我把主張與來源的逐條比對提前到大綱節點，新增兩個檢查：「這個數字是研究結論還是例子？」以及「這項活動是否符合來源的定義？」修訂後才進入 HTML。最後一關則檢查導覽和引用能否操作。
